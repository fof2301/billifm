The problem

Audio fiction has never once listened back.

A podcast plays. An audiobook plays. Even a "choose your path" app just plays a different pre-recorded branch. The person on the other end can't hear you, doesn't remember what you said a minute ago, and can't be surprised by the actual question you asked.

What you get today

Fixed lines. Fixed branches. The same scene plays out the same way, however many times you open it.

What this is instead

A character who's actually listening, has something to hide, and a clock that keeps moving whether or not you say anything at all.

What we built

A story is a folder. The framework does the rest.

Story Framework plays 5–10 minute interactive stories in a mobile browser: one fixed scene, AI characters you can talk to, a clock that runs whether you act or not. Nothing story-specific lives in the framework's own code — every story ships as a JSON bundle plus assets, and the framework just plays it.

The characters

It's not a script. It's a person with something to hide.

Every character is an authored persona — a personality, a voice, secrets they only give up under conditions the author set, and hard limits they never cross. Talk your way through a challenge however you like: an LLM judge reads the whole conversation against a rubric you never see, and decides on its own whether you actually solved it.

The clock

A whole story day, every few real minutes.

An in-story clock turns real minutes into a full day; dawn, day, dusk, and night (or a story's own named phases) crossfade the scene as time passes. Challenges race a countdown of their own — one that pauses whenever a reply is in flight, so network lag never costs you a second of story time.

The format

Stories are data. Not code.

A bundle is story.json (public), secrets.json (server-only — never shipped to a browser), and an assets/ folder. Both files are checked against a schema the moment the server boots; a broken bundle fails loud, before a single player ever sees it — never mid-game.

{
  "meta": {
    "title": "The Cellar",
    "tagline": "You have 3 days. Only you can do this.",
    "genre": "thriller",
    "modes": ["mcq", "text", "voice"]
  },
  "clock": {
    "realMinutesPerStoryDay": 5,
    "totalStoryDays": 3,
    "phases": ["dawn", "day", "dusk", "night"]
  }
}

— an unedited excerpt of stories/kidnapping-escape/story.json

Under the hood

The engine runs in your pocket. The secrets stay on the server.

Browser

Player shell (React) + the engine — state, story clock, timers, all three input modes. Resumes instantly from localStorage.

⇄message / reply + audio

Server

An AI gateway holding the API key and every story's secrets. Assembles prompts, calls the LLM, judges challenges, saves session snapshots to SQLite.

stories/ — story.json + secrets.json + assets, validated against a schema at boot. A broken bundle fails loud, never mid-game.

pnpm monorepo · packages/schema · packages/engine (pure TypeScript, zero DOM or network) · apps/web · apps/server

How we know it works

Tested the same way it ships.

199automated tests, across four workspaces

Plus one Playwright flow, playing a story start to finish against a mocked gateway — deterministic, no AI calls, no API key required. The engine that decides what happens next is pure TypeScript with no DOM and no network, so it's tested the same way whether it ships to a browser or, one day, somewhere else entirely.
