# Game Feel + Onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sound, haptics, motion, and first-play coach marks for the story framework — all web-layer, driven by the engine's existing effect stream.

**Architecture:** `useSession` gains an `onEffect` ref (like `onAudio`). A Stage-level `useFxEvents` hook translates engine effects + state observation into a small `FxEvent` vocabulary (including inferred `challenge-succeeded`). Independent consumers: `useSound` (decision layer over a thin Web Audio backend, synthesized cues + generative ambient with `scene.ambientAudio` file override), `useHaptics`, `PhaseToast`, `TypewriterText`, `CoachMarks`. One "Effects" toggle gates sound+haptics.

**Spec:** `docs/superpowers/specs/2026-07-25-juice-onboarding-design.md` — binding.

## Global Constraints

- No company names anywhere. TypeScript strict; ESM. TDD failing-test-first; conventional commits. YAGNI.
- **No animation libraries; no new runtime dependencies at all.** CSS transitions/animations + Web Audio only.
- No engine/schema/server changes (the `onEffect` ref lives in apps/web's useSession).
- Everything sound/haptic is gated by the Effects toggle (`localStorage['sf-effects']`, default on). The game must remain fully playable muted.
- Thin platform wrappers (Web Audio oscillator calls, navigator.vibrate) are NOT unit-tested; decision layers ARE (same policy as OpenAI providers).
- The Web Audio backend is a module-level lazy singleton (`getAudioBackend()`) so Intro's unlock tap and the Stage share one AudioContext.

### Task 1: `onEffect` seam + `useFxEvents` with success inference

**Files:** Modify `apps/web/src/useSession.ts`; Create `apps/web/src/fx/events.ts`; Test `apps/web/test/fx-events.test.ts` (+ extend `useSession.test.ts`)

**Interfaces (Tasks 2–5 consume):**
```ts
// SessionApi gains:
onEffect: { current: ((e: Effect) => void) | null }   // invoked for EVERY engine effect inside runEffects, before effect-specific handling

// fx/events.ts
export type FxEvent =
  | { type: 'challenge-started'; challengeId: string }
  | { type: 'challenge-succeeded'; challengeId: string }
  | { type: 'challenge-timed-out'; challengeId: string }
  | { type: 'phase-changed'; day: number; phase: string }
  | { type: 'story-ended' }
export function useFxEvents(session: SessionApi, onEvent: (e: FxEvent) => void): void
```

**Behavior:**
- `useSession.runEffects` calls `onEffect.current?.(e)` first for every effect.
- `useFxEvents` keeps the listener in a ref (stable across renders). It subscribes via `session.onEffect` (composing with any existing subscriber is NOT needed — Stage owns the single subscription and fans out).
- Engine effects map 1:1: `CHALLENGE_STARTED`→`challenge-started` (also records `trackedId`), `CHALLENGE_TIMED_OUT`→`challenge-timed-out` (also sets `timedOutId` marker + clears tracking), `PHASE_CHANGED`→`phase-changed`, `STORY_ENDED`→`story-ended`.
- **Success inference:** a `useEffect` watching `session.state.activeChallenge?.id`: when the previously tracked id is no longer active and the `timedOutId` marker doesn't match it, emit `challenge-succeeded` for the tracked id, then clear tracking. (Engine emits no success effect — success arrives as a CHALLENGE_RESOLVED action; spec §3.)

New `fx-events.test.ts` (renderHook with a scripted fake session object — `onEffect` ref + mutable `state`): challenge-started forwarded; timeout forwarded and NOT followed by success when the challenge clears; success emitted when tracked challenge leaves `activeChallenge` without a timeout marker; phase/story events forwarded. ### Task 2: Sound — backend, decision controller, prefs, unlock, ambient

**Files:** Create `apps/web/src/fx/audio.ts`, `apps/web/src/fx/sound.ts`, `apps/web/src/fx/prefs.ts`; Modify `Intro.tsx` (unlock on Begin/Resume tap), `SettingsSheet.tsx` (Effects toggle), `Stage.tsx` (wire controller: fx events + per-second `tickCheck(remainingMs)` from a `useEffect` on `state.elapsedRealMs` + ambient start/stop on mount/unmount + duck on phase change); Test `apps/web/test/sound.test.ts`

**Interfaces:**
```ts
// fx/prefs.ts
export function effectsEnabled(): boolean            // localStorage 'sf-effects' !== 'off'
export function setEffectsEnabled(on: boolean): void

// fx/audio.ts — UNTESTED thin backend
export interface AudioBackend {
  unlock(): void                                     // resume/create AudioContext (call from a user gesture)
  playSting(): void
  playResolve(): void
  playThud(): void
  playBell(): void
  playTick(): void
  startAmbient(sceneId: string, fileUrl?: string): void  // fileUrl (assetUrl-resolved) wins over synthesis
  duckAmbient(): void                                // dip ambient gain to 20% for ~1.5s, then restore
  stopAmbient(): void
}
export function getAudioBackend(): AudioBackend      // lazy singleton

// fx/sound.ts — TESTED decision layer
export function createSoundController(backend: AudioBackend, enabled: () => boolean): {
  handle(e: FxEvent): void            // sting/resolve/thud/bell/duck per spec table
  tickCheck(remainingMs: number | null): void  // plays one tick per call while 0 < remainingMs < 30_000
  startAmbient(sceneId: string, fileUrl?: string): void
  stopAmbient(): void
}
```

**Backend recipes (implement exactly; all through a master GainNode at 0.5):** sting = sawtooth 110→55 Hz over 0.25 s, gain envelope 0.3→0; resolve = two sequential sine notes 523 Hz then 659 Hz, 0.12 s each at 0.2; thud = sine 70 Hz, 0.3 s, fast exponential decay from 0.4; bell = triangle 880 Hz, 1.2 s exponential decay from 0.25; tick = square 1500 Hz, 0.03 s at 0.15. Ambient synthesis: looped AudioBufferSource of generated noise through a lowpass BiquadFilter — `sceneId === 'cellar'`: brown-ish noise, lowpass 120 Hz, gain 0.05, plus a 55 Hz sine at 0.02; any other scene: white noise, lowpass 800 Hz, gain 0.03. `fileUrl` present → HTMLAudioElement, `loop = true`, `volume = 0.25` instead. Every method silently no-ops if the context isn't unlocked yet.

**Controller decisions (the tested part):** `challenge-started`→sting; `challenge-succeeded`→resolve; `challenge-timed-out`→thud; `story-ended`→bell + stopAmbient; `phase-changed`→duckAmbient. `tickCheck`: tick only when enabled() and remaining in (0, 30_000). Everything no-ops when `enabled()` is false (including start/stop ambient — but stopAmbient always passes through so muting mid-game silences).

**Wiring:** Stage builds the controller once (useMemo), fans fx events to it, calls `tickCheck(state.activeChallenge ? state.activeChallenge.deadlineMs - state.elapsedRealMs : null)` in a `useEffect` on `state.elapsedRealMs`, `startAmbient(bundle.scene.id, bundle.scene.ambientAudio && assetUrl(bundle.meta.id, bundle.scene.ambientAudio))` on mount, `stopAmbient` on unmount. Intro: `getAudioBackend().unlock()` inside the existing `start()` handler. SettingsSheet: "Effects" row with a toggle button (aria-pressed, label "Effects"), reading/writing prefs; muting calls `getAudioBackend().stopAmbient()`; unmuting restarts ambient via a Stage-held callback prop — simpler: SettingsSheet only writes the pref; Stage watches it via a `settingsOpen` close and re-syncs ambient (start if enabled, stop if not).

**TDD:** `sound.test.ts` with a fake backend (vi.fn per method): cue mapping per event; tickCheck boundaries (null, 31 s, 29 s, 0); mute gating (enabled=false → no calls except stopAmbient); ambient file-vs-synth passthrough args. RED → implement → GREEN. Commit `feat(web): synthesized sound layer with ambient and effects toggle`.
